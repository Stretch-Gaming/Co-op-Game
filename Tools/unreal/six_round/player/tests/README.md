# Native PG input gate packet

These files are staged and unrun by the worker. Offline syntax/parser checks do not prove Blueprint transpilation, input execution, devices, rendering or a walked mission. Each asynchronous test returns `queued`; acceptance is its later JSON report with `passed: true`, not the queue receipt.

Use only the six-round editor8061 and `/Game/Puzzles/Test/SixRound/L_SixRound_Test`. Do not use another task's editor/map. Compile/save primary input/axis, tools, traversal, health, spectator, cage/taking, secondary-keyboard and test-map integration first. The primary owns every editor call. Run one test at a time, watch its report, and inspect the Output Log before moving on. Start a fresh PIE session for independent gates that move a statue, kill a player or pick up the key.

Execution order:

1. `player/tests/offline_validate.py` locally: Python AST checks, unchanged Epic native DSL parser for the five keyboard-authoring graphs, terminal-execution checks, source hashes, and an allowlist showing input tests call only query functions. It does not contact Unreal or create assets.
2. Primary runs `player/build_secondary_keyboard.py` after new `IA_P2Flare` and `IA_P2Climb` reservations. It writes only Core controller, run context and those two input actions. Existing RightShift prefix injects `IA_Sprint`; RightAlt and P add flare/climb. The primary then removes the character's retired `IA_Brace` binding in its own integration script.
3. Run `player/tests/preflight.py` outside PIE. It reads saved custom-event flags, handler links, Forward float pin and key mappings. Required custom events: `Server_ThrowFlare`, `Server_Climb`, `Server_StopClimb`, `Server_SetClimbForward`, all Run on Server and Reliable. Add Forward float through the UI before running primary `axis_ready` integration. The test never edits flags or graphs.
4. Prepare network PIE and wait until the roster and owning contexts settle. Every test requires `players: 2/3/4`, `profile: joining/host_split` and `_during_pie: true` in queue arguments. Joining mode uses `PIE_Client`, N clients and a separate authority world. Host split uses `PIE_ListenServer`, N−1 initial connections, then native F5 in Lobby adds the second host local owner. At N4 this is exactly two joining client worlds plus two host-local controllers. One process is required for native inspection. The harness verifies actual server/dedicated/standalone network mode through public Blueprint networking queries, controller ownership, replicated roster/ColorSlots and independent local-player input subsystems.
5. Run the gates below at their required states. Preserve the reports under `Saved/SixRound` and the primary command receipt/source hash. A timeout, assertion or missing prerequisite is a failed/unrun gate, never a partial pass.
